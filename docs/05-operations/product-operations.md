# 产品运营与研究质量闭环

状态：运营方案；当前无工作台或自动运营看板，受控CLI阶段通过人工登记执行。FR-014为后续平台功能。

## 1. 开放与使用

先向获授权的内部研究用户开放，登记工作空间、角色、批准市场、模型/数据来源、月预算和负责人。培训必须包含数据缺失、REVIEW、历史时点、回测评分局限及报告复核；不能将“Buy”解释为自动下单。

首周固定小规模标的与统一配置，记录所有任务，包括失败、超时和取消；新增市场/crypto需单独核验身份、数据覆盖、币种、日历和质量，不只因Yahoo能查到就开放。

## 2. 指标口径

| 指标 | 分子 / 分母与维度 | 动作 |
|---|---|---|
| 激活 | 当周至少1个成功且被读取的报告用户 / 新获授权用户 | 检查权限、配置、培训 |
| 有效完成率 | 终态succeeded / 已进入终态的有效任务；取消单列 | 按供应商、市场、模型定位 |
| 复核效率 | 创建到复核的p50/p95；approved / 已复核报告 | 优化证据可读性和责任分派 |
| REVIEW/缺失率 | REVIEW或关键证据缺失报告 / 全部生成报告 | 检查数据/结构化/提示词 |
| 人工纠正率 | 有事实纠正报告 / 已复核报告 | 按问题来源补充回归 |
| 单报告成本 | 全部模型/数据/重试费用 / 成功报告数 | 同时展示失败浪费与unknown账单 |
| 反馈闭环 | 已关闭且有证据反馈 / 到期应处理反馈 | 追踪超期与重复问题 |

控制面可用性、任务恢复和预算监控见[观测手册](../06-runbooks/observability.md)。alpha/方向命中是研究评估指标，不是产品活跃或资金净值指标。低REVIEW率不一定是质量提升，需与事实错误率一起判断。

## 3. 日、周、月节奏

每日检查失败/超时、供应商不可用、缺失/REVIEW、费用突增、待复核和反馈；按[故障手册](../06-runbooks/incident-response.md)升级。每周按固定评估集复核模型输出、对比数据覆盖与费用，生成纠正案例和发布建议。每月审核预算、用户/角色、来源授权、保留期、模型退役和恢复演练计划。

报表保留统计区间、UTC/市场时区、版本、分母、未知值与样本量；不把unknown cost补0，不排除失败后只展示好结果。

## 4. 反馈SOP

反馈输入：task_id、report_version、问题分类、证据、影响、复现说明。运营分派数据负责人（身份/时点/价格/缺失）、模型负责人（幻觉/输出/语言）、工程负责人（状态/授权/保存）或体验负责人。

建议响应：疑似跨租户、时点泄漏、错误公司/价格影响多数用户立即升级SEV1；单用户阻断当天响应；一般体验3工作日内分派。关闭需说明根因、修复版本、回归结果、是否重算/撤回报告与通知范围。

## 5. 责任与试运行退出

产品负责人管理范围与验收，研究负责人管理报告复核，模型/数据负责人管理质量，运营管理反馈与报表，SRE管理服务保障。扩大范围前必须具备稳定观察窗口、已关闭严重问题、批准预算与SLO，并完成[验收清单](../04-testing/acceptance-checklist.md)对应阶段。
