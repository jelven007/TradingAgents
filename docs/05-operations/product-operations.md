# 产品运营与研究质量闭环

状态：2026-10-25当前运营规则。面向产品/运营/复核员，运营责任角色依据工作台、operations查询和账本维护，指标/来源/预算变化、事件处置后及每周复核。已有中文工作台、个人关注、报告、累计准入、暂停/冻结和对账；自动指标告警及FR-014正式反馈管理待建。

## 1. 开放与使用

本机用户原账号登录8783，选择股票/问题即可开始；首次管理员配置真实模型并逐层测试/保存。可信模板控制目录开放范围，显示来源更新日及推荐基准。培训解释Insufficient、REVIEW、来源许可、未复核状态和FX日期，不能将买入/减持当成账户指令。生产开放登记角色、来源许可、范围和实际费用策略。

首周固定小规模标的与统一配置，记录所有任务，包括失败、超时和取消；新增市场/crypto需单独核验身份、数据覆盖、币种、日历和质量，不只因Yahoo能查到就开放。

## 2. 指标口径

| 指标 | 分子 / 分母与维度 | 动作 |
|---|---|---|
| 激活 | 当周至少1个成功且被读取的报告用户 / 新获授权用户 | 检查权限、配置、培训 |
| 有效完成率 | 终态succeeded / 已进入终态的有效任务；取消单列 | 按供应商、市场、模型定位 |
| 复核效率 | 创建到复核的p50/p95；approved / 已复核报告 | 优化证据可读性和责任分派 |
| REVIEW/缺失率 | REVIEW或关键证据缺失报告 / 全部生成报告 | 检查数据/结构化/提示词 |
| 研究完整率 | complete快捷报告 / 全部快捷报告，insufficient单列；再按quality/复核状态切片 | 不能以任务succeeded替代完整观点或可发布报告 |
| 默认路线开销 | 每任务记账调用、输出tokens、预留/已对账/unknown分别列出 | 快捷最多8次，预留不当账单；超界查路线/重试 |
| 人工纠正率 | 有事实纠正报告 / 已复核报告 | 按问题来源补充回归 |
| 单报告成本 | 全部模型/数据/重试费用 / 成功报告数 | 同时展示失败浪费与unknown账单 |
| 反馈闭环 | 已关闭且有证据反馈 / 到期应处理反馈 | 追踪超期与重复问题 |

控制面可用性、任务恢复和预算监控见[观测手册](../06-runbooks/observability.md)。alpha/方向命中是研究评估指标，不是产品活跃或资金净值指标。低REVIEW率不一定是质量提升，需与事实错误率一起判断。

## 3. 日、周、月节奏

每日检查失败/超时、供应商不可用、缺失/REVIEW、费用突增、待复核和反馈；按[故障手册](../06-runbooks/incident-response.md)升级。每周按固定评估集复核模型输出、对比数据覆盖与费用，生成纠正案例和发布建议。每月审核预算、用户/角色、来源授权、保留期、模型退役和恢复演练计划。

报表保留统计区间、UTC/市场时区、版本、分母、未知值与样本量；不把unknown cost补0，不排除失败后只展示好结果。

本地 `operations`包含全部任务终态、报告积压/过期、调用数、预留额、已对账额和费用unknown；`reconcile`按账单行一次性固定micro-USD，冲突拒绝。工作空间预算是所有已准入任务预算的累计额度，取消不释放，不等于月费用。费用只覆盖模型调用，数据/基建/人工不在当前成本查询中。

`experiment`保留计划样本、未提交、未计划/歧义任务、失败/取消/REVIEW、报告撤回和pending；`prediction`可读原始窗口收益。短窗口interim不得作为长期研究的最终判定，final仅表示期限覆盖。prospective须事前计划并在入口session前发布/固定预测，diagnostic历史模型事后知识unknown；显式日历/价格文本须运营者核定，示例合成价不能计入真实业绩。

Insufficient报告可能对应succeeded任务，因为保存/完整性接受成功，但分析不完整；必须同时报告执行状态、研究完整度、质量和复核状态，不能用单个成功率宣传产品。当前operations未自动汇总所有新增产品指标，缺少自动看板项通过授权报告抽样核实，不把建议指标称为已上报数据。

目录每次更新核对源总数、终止空页、唯一代码和特殊币种，发现旧/退市代码先查真实行情，不自动编价格。新增来源许可须附真实授权依据；unknown许可草稿可读但不能批准发布。单一真实NVDA结果不能代表所有目录对象的数据质量或投资胜率。

## 4. 反馈SOP

反馈输入：task_id、report_version、问题分类、证据、影响、复现说明。运营分派数据负责人（身份/时点/价格/缺失）、模型负责人（幻觉/输出/语言）、工程负责人（状态/授权/保存）或体验负责人。

建议响应：疑似跨租户、时点泄漏、错误公司/价格影响多数用户立即升级SEV1；单用户阻断当天响应；一般体验3工作日内分派。关闭需说明根因、修复版本、回归结果、是否重算/撤回报告与通知范围。

失败恢复引导“使用推荐配置重新研究”，保留股票/问题并恢复当前日期、原币种和8次推荐上限；旧任务及费用仍保留。出现模型空正文先查输出额度/截断，预算不足先查固定路线和预留，不让入门者自行试JSON或盲增费用。个人核实笔记不是运营工单，正式反馈仍按本节人工记录；对外发送消息需另有用户授权。

## 5. 责任与试运行退出

产品负责人管理范围与验收，研究负责人管理报告复核，模型/数据负责人管理质量，运营管理反馈与报表，SRE管理服务保障。扩大范围前必须具备稳定观察窗口、已关闭严重问题、批准预算与SLO，并完成[验收清单](../04-testing/acceptance-checklist.md)对应阶段。
