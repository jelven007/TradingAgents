# 文档控制、责任与维护

基线 `PROD-DOC-1.0`，日期2026-10-23，来源`main@e8f5503`。状态：本次工程与文档交付；生产需求/指标/选型/排期待相关责任方评审。没有业务签署或生产上线记录。

## 1. 文档层次与唯一来源

项目分析记录代码事实，PRD定义FR/NFR，流程定义领域语义；架构/ADR说明方案与权衡；开发计划定义DEV任务；测试策略、追踪矩阵与验收清单连接需求和证据；运营/运维记录行为及处置；治理定义发布、风险与维护。

需求ID仅在PRD创建，其他材料引用；任务ID仅在实施计划定义。验证结果只写实际执行，SLO/保留期/容量建议必须标明待确认。原始上游README与CHANGELOG属于来源，不作为本地生产状态声明。

## 2. 状态词

“已实现”必须有代码和适用范围；“部分实现”明确缺口；“目标待建”只有设计；“本次完成”是当前交付行动；“待验证”尚无运行证据；“已验收”需责任人确认且附版本/环境/日期。不得以离线模拟证明真实模型、生产性能或恢复目标。

## 3. 维护责任

产品维护需求/流程/运营；架构维护设计/ADR；工程维护开发/目录/配置；QA维护追踪矩阵/测试/验收；模型/数据维护质量治理；SRE维护部署/监控/故障/恢复；项目负责人维护风险及发布责任。默认角色尚未指定个人。

需求变更时同步PRD→方案→任务→矩阵→验收；代码路径或入口变更同步README/开发/部署/CI；新测试与测量更新验证记录；上线或事故更新运维及风险。每周检查活跃需求，发布前完整核对。

## 4. 自动与人工检查

`python scripts/check_docs.py`校验维护文档本地Markdown文件链接、PRD与矩阵需求集一致及未知编号。它不校验远端链接、Markdown锚点、Mermaid语义、真实业务完成或原始归档README；人工必须核对状态、范围、SLO口径、样本分母、责任人与跨文档一致性。

变更记录：本基线新增中文工程入口、代码事实分析、15项功能需求及8项非功能需求、生产方案、3项ADR、开发分解、测试门禁、运营、运维和治理。后续新增版本需记录变更原因、影响需求、批准人和生效时间。
