# 变更、发布与上游同步

状态：2026-10-24。本轮六次增量在 `9dd5b06` 基线工作区实现并离线验证，未新增commit、push或外部发布；逐轮证据见[迭代记录](../03-development/iteration-log.md)。S1/S2已有本地子集，公司基础设施/生产部署与业务签署仍待完成。

## 1. 变更分类与责任

工程/目录变更验证import、打包、资源与回归；模型/prompt变更验证schema、事实、时点、评级与费用；数据变更验证来源许可、known_at、覆盖、修订及fallback；数据库/存储变更验证迁移、隔离、备份和回滚。

开发负责人负责实现与证据，QA确认覆盖，模型/数据负责人确认研究质量，SRE确认运行与恢复，产品负责人确认范围，安全确认权限与敏感数据。角色可兼任但签署责任不能消失。

## 2. 发布流程

冻结需求/版本→代码评审→lint/文档/离线测试→wheel与镜像检查→真实契约/质量/安全/恢复验收→批准小范围灰度→监控→扩大或回滚。仅S0文件交付不触发部署批准；实际服务发布前必须有可运行候选版本与证据。

发布记录包含代码SHA、应用版本、依赖锁hash、镜像digest、配置/prompt/model/数据策略版本、schema版本、测试结果、灰度范围、回滚目标和责任人。候选阻断：新时点泄漏/越权、重要事实错误、幂等/恢复失败、严重未处置漏洞、备份失效。

## 3. 版本与兼容

当前 `0.7.0`保留来源值，不能把本地改动当作官方0.7.0发布。自有发布先采用独立版本与changelog，修改version单一来源；release tag需匹配包版本。上游CHANGELOG作为来源保留，本地版本历史另加条目时明确fork范围。

接口schema变更需兼容期；数据库采用expand→migrate→contract。回滚代码/配置不等于可逆数据库迁移，破坏性改动之前必须备份、迁移统计与演练。模型回滚保持旧report/manifest不可变，不改写历史评级。

## 4. 上游更新

仅跟踪用户指定origin。每次 `git fetch origin`记录默认分支新SHA，在隔离分支比较与测试后合入；新路径依[迁移映射](../03-development/directory-migration.md)调整，不能将上游根包和src包同时保留。

确认许可证、依赖/模型变化、prompt和时点修复；重新生成uv.lock和requirements.lock，记录uv版本与差异，冻结依赖后执行门禁。只有锁文件变更或新失败才扩大依赖验证，不例行盲升全部包。

## 5. 紧急回滚与文档同步

故障先暂停扩大流量及受影响发布，切回已验证镜像/配置，保留任务/审计，检查in-flight旧attempt。紧急变更仍须记录原因和风险并事后补测试/评审。

每个需求状态变化同步PRD、追踪矩阵、实现计划、验收清单与验证记录；每次发布修订部署/故障/恢复手册。文档审阅与业务批准不同，本次文档为待评审基线。
