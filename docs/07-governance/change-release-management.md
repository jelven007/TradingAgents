# 变更、发布与上游同步

状态：2026-10-25当前仓库交付规则；面向工程/QA/发布负责人，工程责任角色依据Git、PR、CI和验证记录维护，每次合并/依赖/兼容变更复核。当前工作包括股票研究与本机产品增量、全链文档、fresh验证、推送并合入origin/main；实际SHA/PR/合并状态以版本控制为唯一事实，历史“未提交”不代表当前状态。生产部署/业务签署另验。

## 1. 变更分类与责任

工程/目录变更验证import、打包、资源与回归；模型/prompt变更验证schema、事实、时点、评级与费用；数据变更验证来源许可、known_at、覆盖、修订及fallback；数据库/存储变更验证迁移、隔离、备份和回滚。

开发负责人负责实现与证据，QA确认覆盖，模型/数据负责人确认研究质量，SRE确认运行与恢复，产品负责人确认范围，安全确认权限与敏感数据。角色可兼任但签署责任不能消失。

## 2. 发布流程

冻结需求/版本→代码评审→lint/文档/离线测试→wheel与镜像检查→真实契约/质量/安全/恢复验收→批准小范围灰度→监控→扩大或回滚。仅S0文件交付不触发部署批准；实际服务发布前必须有可运行候选版本与证据。

发布记录包含代码SHA、应用版本、依赖锁hash、镜像digest、配置/prompt/model/数据策略版本、schema版本、测试结果、灰度范围、回滚目标和责任人。候选阻断：新时点泄漏/越权、重要事实错误、幂等/恢复失败、严重未处置漏洞、备份失效。

仓库交付流程：确认工作区全量范围→核对origin/main→更新文档及矩阵→本次lint/文档/全量回归/前端构建/包smoke→审查暂存diff和敏感数据→独立commit→推送当前分支→创建PR并查看CI/保护规则→在核对head SHA后合并main→fetch并更新本地main。用户已授权本轮推送及合并，无需另增审批；远端保护规则与失败checks不能绕过。不得force-push、重写main、删除用户分支或提交runtime/.env/token。

PR包含问题/行为、需求编号、验证命令/计数、兼容/回滚、真实与合成证据边界。合并方法优先merge保留既有提交；若仓库只允许其他方式，按实际配置选择并报告。发布仓库代码不等于创建release tag、上传发行包、云部署或开放生产服务，此轮不触发这些外部发布。

## 3. 版本与兼容

当前 `0.7.0`保留来源值，不能把本地改动当作官方0.7.0发布。自有发布先采用独立版本与changelog，修改version单一来源；release tag需匹配包版本。上游CHANGELOG作为来源保留，本地版本历史另加条目时明确fork范围。

本机已新增账号/session、模型/研究revision、关注等SQLite表，使用CREATE IF NOT EXISTS兼容初始化，不删除既有账号/任务。API原tasks仅提交行为保持，research组合执行、instruments和watchlist是新增接口；专业API默认full，工作台默认guided_stock。旧任务固定实现指纹及模型revision，源码变化后不能保证重跑旧queued任务，需保留旧记录并以新任务恢复。短期本地数据库兼容不代表生产expand/contract迁移治理。

接口schema变更需兼容期；数据库采用expand→migrate→contract。回滚代码/配置不等于可逆数据库迁移，破坏性改动之前必须备份、迁移统计与演练。模型回滚保持旧report/manifest不可变，不改写历史评级。

## 4. 上游更新

仅跟踪用户指定origin。每次 `git fetch origin`记录默认分支新SHA，在隔离分支比较与测试后合入；新路径依[迁移映射](../03-development/directory-migration.md)调整，不能将上游根包和src包同时保留。

确认许可证、依赖/模型变化、prompt和时点修复；重新生成uv.lock和requirements.lock，记录uv版本与差异，冻结依赖后执行门禁。只有锁文件变更或新失败才扩大依赖验证，不例行盲升全部包。

## 5. 紧急回滚与文档同步

故障先暂停扩大流量及受影响发布，切回已验证镜像/配置，保留任务/审计，检查in-flight旧attempt。紧急变更仍须记录原因和风险并事后补测试/评审。

每个需求变化同步PRD、矩阵、开发、验收和验证；行为变化同步运营/部署/事件/恢复及风险。日期、责任路径、真相来源和陈旧信号在[文档控制](document-control.md)登记；历史记录标明非当前指导，不原地改写已发生的验证结果。文档审核、仓库合并与业务/生产批准是不同事件。
