# 模型、提示词、数据与评估治理

状态：2026-10-24。生产目标与本地增量并列；适用于 FR-004、FR-007、FR-008、FR-011、NFR-003。已有输入/实现/证据hash、独立质量、固定复核版本及期限观察，操作见[本地手册](../03-development/managed-research.md)。配置冻结不意味着模型输出确定性。

## 1. 版本登记

模型登记包含供应商、地区、模型ID、实际版本、上下文限制、结构化能力、工具支持、温度/推理参数支持、价格版本、批准范围及到期检查。使用 `latest` 等浮动别名时，报告必须标注无法完全冻结。

提示词版本包含角色、模板、输出schema、工具白名单、语言规则、变更理由与测试/评估结果；schema改动须检查评级解析、report renderer和记忆兼容性。配置版本引用模型、prompt、vendor链、轮次、预算、语言、benchmark和质量策略，不允许运行中修改。

## 2. 数据可知时间

event_time 是经济事件或行情时点；known_at 是当时可被使用者知道的时点；fetched_at 是本系统采集时间。历史评估只允许 known_at ≤ cutoff 的证据；晚披露的财务数据、修订值、后来的复盘不能反向注入。存储供应商原始时区并转UTC，对缺失或模糊日期保守处理。

每个来源登记支持市场、延迟、披露/修订语义、费用、速率、授权用途、可存储字段与保留期限。SEC filed数据保留 accession及披露时间；Yahoo未提供的历史披露时间不能猜测。FRED历史数据要区分发布与修订/vintage，无法确认时禁止作严格时点证据。新闻与社交只存授权内容，删除或许可到期后可重放能力受限，需在manifest说明。

## 3. 保留与删除

| 对象 | 候选保留 | 处理规则 |
|---|---|---|
| 任务、报告、配置、审计 | 365天 | 按公司政策审批；原始版本不原地修改 |
| 原始行情/新闻/社交快照 | 90天上限候选 | 供应商许可更短时从其规定；按字段白名单采集 |
| 可重建缓存 | 7天 | 到期可删除，不作为唯一审计依据 |
| 持仓快照 | 随报告期限、最小化 | 脱敏，账户标识独立授权 |
| 孤立attempt对象 | 7天宽限候选 | 核验无任务/审计引用且无有效租约后回收 |

上述数值待业务及法务确认。法律保留、许可限制或隐私删除冲突由责任方决定，禁止自行延长来源许可。不能留存原始内容时保存允许的元数据和hash，并明确“不能重放正文”。

## 4. 质量与发布评估

固定评估集按市场、资产类型、流动性、行情缺失、历史披露、新闻注入、语言和模型能力分层。至少包含标的身份错误、过期价格、数据源不可用、结构化失败、REVIEW、跨日期记忆和高并发。基线先使用离线脚本模型保证链路，再用受控真实供应商样本验证输出质量。

质量指标：事实/价格引用可核验率、未来信息泄漏次数、schema成功率、评级可解析率、REVIEW率、缺失数据诚实表达、人工纠正率、token/成本、耗时。泄漏或跨租户暴露为零容忍；模型切换不得使关键用例退化。候选阈值：同一评估集事实可核验率≥95%，均值成本增幅≤10%，p95耗时增幅≤20%，需负责人批准且置信区间/样本量随结果公布。

投资方向评估与工程正确性分开：报告样本数、pending、失败、未评分、按评级方向命中及alpha分布，采用时间划分而非随机泄漏。重复采样报告均值、分散程度和模型版本；不使用单次评级或成功样本筛选宣称策略收益。真实交易评估需另立资金、成本和成交模型。

本地评估固定显式交易session列表、模板hash、期限、币种、基准和价格口径，Decimal计算相同起止日的标的收益、基准收益及两者之差。未复权收盘、拆股复权收盘和总收益指数分开；收益未包含资金、持仓、交易成本或成交。短窗口标为interim，完整窗口标为final仅表示期限覆盖，不表示投资结论正确；REVIEW/blocked、未提交、失败、取消、pending和撤回报告保留在分母及状态中，不计算策略净值/Sharpe。

prospective计划须早于所有样本研究日，任务/报告完成/发布/登记须按时间顺序且早于入口session；未来日只允许计划，任务仍拒绝未来分析日。diagnostic可以观察历史任务，但模型事后知识标为unknown，不能改称严格历史回测。session日历和价格来源文本由运营者提供，系统计算并留存hash；没有内置交易所日历、独立真实性验证或许可自动核验。长期真实前瞻样本、统计推断、自动网格调度与反馈平台仍待完成。

## 5. 运营闭环

每周模型/供应商检查价格、退役计划、能力及契约；重大变更经过评估→隔离试运行→受控生效→监控→回滚。旧报告保留旧版本，新版本不回写历史。质量事件按[故障手册](../06-runbooks/incident-response.md)处置，模型/数据负责人签署根因和修正样本。
