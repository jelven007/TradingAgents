# 产品需求与验收基线

状态：需求仍待业务评审，2026-10-24，`PROD-DOC-1.0`增量。本文件是需求编号唯一来源。2026-10-23原始分析见[项目分析](../00-overview/project-analysis.md)，本地增量实现与外部待验收项见[追踪矩阵](traceability.md)和[逐轮记录](../03-development/iteration-log.md)。

## 1. 产品目标与边界

面向内部研究员、研究负责人、模型管理员、运营和运维，建立可追溯、可控制成本、可人工复核的金融研究平台。第一阶段只交付研究报告、评级与评估，不接受券商交易指令，不管理真实资金，也不承诺盈利。

成功应通过“任务可靠完成、证据可追溯、质量可评估、成本可预测”衡量。先完成单租户受控试运行，验证任务与证据契约，再开放多租户。股票/ETF 为首个验证范围；跨市场和 crypto 只有在供应商、日历、币种与质量评估齐备后开放。

角色：研究员创建任务、看自己的工作空间报告；研究负责人复核、批准报告；模型管理员维护模型与提示词版本；运营读取脱敏使用和质量指标；运维读取服务状态，不默认具有持仓或报告正文访问权。

下表为建议目标，不是已有测量结果；上线前必须用代表性负载确认预算并由责任人批准。

| 编号 | 优先级 | 目标与验收口径 |
|---|---|---|
| NFR-001 | P0 | 控制面月可用性 ≥99.5%；任务提交/查询 p95 ≤500ms，排除模型执行耗时；在固定环境、20并发、至少1000请求下测量 |
| NFR-002 | P0 | 单任务默认 deadline 15分钟，超时60秒内进入终态；故障注入后成功恢复且最终只有一份被接受的决策，允许外部模型调用发生重试 |
| NFR-003 | P0 | 配置和证据快照可重放；代码/依赖/模型/提示词版本齐备率100%；不要求模型逐字确定性，未知供应商版本须明确记录 |
| NFR-004 | P0 | 密钥不写入版本库、报告、日志；存储/传输加密，跨租户负面测试全部通过；审计访问权限单独授予 |

## 4. 范围与业务决策

必须在生产 S1 准入前确认：初始用户/工作空间数量、可用模型与地区、行情商业授权、每任务及每月预算、首批标的、保留期、身份提供方。暂按公司内网、单区域、低频研究、20并发控制面请求设计，worker 初始并发 2，非吞吐承诺。本地实现默认deadline为1800秒，工作空间额度为累计已准入任务预算；尚未证明15分钟建议目标、月账单上限或供应商费用预测。

候选保留策略：任务/报告/审计365天，原始数据90天（受供应商许可约束），可重建缓存7天；详细限制见[数据治理](../02-architecture/model-and-data-governance.md)。市场、用途或授权范围变化必须重新评估。

订单、确定性交易风控、成交、清算、资金、移动应用不在 S0–S2 范围。研究评级的 `Buy` 不能直接映射生产订单。

## 5. 优先级与完成定义

P0 是进入受控服务试运行的必要能力，P1 在试运行稳定后扩展。单条需求完成需同时具备实现、测试、运行证据、文档及责任人确认；现有 SDK 功能只证明核心能力，不等于对应平台需求全部完成。阶段完成条件见[验收清单](../04-testing/acceptance-checklist.md)。
