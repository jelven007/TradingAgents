# 业务流程与领域规则

状态：生产设计。现有 CLI/SDK 只实现分析及文件保存，不具备下述完整平台流程。

## 1. 研究任务

研究员选择工作空间、标的、资产类型、分析日、分析师、持仓版本和配置版本。服务先检查身份权限、输入、预算，再生成任务及 outbox 事件。worker 领取任务、冻结输入版本、采集证据、运行分析图、保存结果；负责人读取证据与缺失项后复核。

任务状态：`queued → running → succeeded | failed | cancelled | timed_out`。重试是同一任务的新 attempt，不新增业务任务；终态不可被旧 worker 改写。报告单独使用 `draft → review_required → approved | rejected → published`，任务成功不代表报告已获准发布。撤回发布生成新事件，不删除历史。

## 2. 复核与发布

复核对象是固定 `report_version`。出现 REVIEW、数据不足、来源冲突、过期行情、估计价格或无法核验引用时进入 `review_required`。复核人不能修改模型原始输出；修订创建新版本并注明依据。权限与职责见[安全设计](../02-architecture/security-model.md)。

“报告发布”表示授权工作空间内可见，不表示订单批准或交易执行。初期不提供公共外链。

## 3. 持仓上下文

未提供持仓 = 未知账户，不按空仓解释。提供 `positions=[]` = 明确空仓。持仓快照需要工作空间、账户标识、币种、快照时间、来源及版本；分析过程中不自动回写持仓。跨币种建议只有明确 FX 来源与时点后才能量化，初期超出支持范围时进入复核。

## 4. 历史研究与评估

历史任务以市场本地分析日结束作为证据 cutoff，并同时保存 UTC instant 与市场时区。文档日期是可读表示，不能替代 instant 校验。原始数据记录 event_time、published_at/known_at、fetched_at；未知披露时间的数据不能用于严格历史评估。

回测由实验负责人冻结 ticker/date 网格、配置、快照集、重复采样策略和 benchmark。各单元结果分别保存；无法分析、未结算与 REVIEW 单列，不可排除后只呈现成功结果。对照实验必须隔离记忆，不利用较晚实验的收益或复盘污染较早时点。

当前上游回测只评价独立评级；对收益精度、非归档文本和持仓不演化的限制必须随评估结果展示。

## 5. 反馈闭环

用户反馈绑定 task_id、report_version、引用证据、问题分类和可复现说明。运营排查后分派数据、模型或工程负责人；修复需对应回归案例、模型评估和新版本记录。关闭反馈需要给出处理结果及新旧版本影响，不以“重跑看起来正常”代替根因。

## 6. 异常判定

| 情况 | 行为 | 禁止行为 |
|---|---|---|
| 非法 ticker / 未来日期 | 在创建阶段拒绝 | 已发起模型后才校验 |
| 供应商不可用 | 按冻结链降级，记录数据质量；关键证据不足则复核或失败 | 把断网解释为公司无数据 |
| 模型格式失败 | 记录结构化/文本回退，评级不可解析则 REVIEW | 自动转成 Hold |
| 预算用尽 / 超时 | 停止新增调用，保留进度及失败原因 | 无限自动重试 |
| checkpoint 不匹配 | 新 attempt 从有效阶段开始，旧状态留存审计 | 混用新旧模型结果 |
| 用户取消 | 协作式取消，保存已消耗成本；外部请求可能已发生 | 承诺撤销已发出的付费调用 |
