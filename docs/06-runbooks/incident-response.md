# 故障、数据质量与模型事件响应

状态：2026-10-24，受控运行SOP。managed已提供暂停提交/冻结发布、租约/取消/超时、费用unknown与hash恢复；操作见[本地手册](../03-development/managed-research.md)。集中告警、云队列和工作台仍待建。

## 1. 分级和职责

SEV1：跨用户数据暴露、时点泄漏、错误公司/价格影响多报告、服务大范围不可用或费用失控；立即停止相关发布/新任务。SEV2：供应商持续不可用、worker积压、部分任务失败、备份超时；当天定位和恢复。SEV3：单份报告表达/体验问题，可进入反馈排期。

建议SEV1确认≤15分钟，SEV2≤1小时，均需值班策略与业务确认，不是目前SLA承诺。SRE负责服务止损，数据/模型负责人负责研究质量，安全负责权限/凭据事件，产品负责人决定撤回与用户通知范围。

## 2. 通用步骤

记录事件ID、时间、环境、代码/配置版本、task/attempt/report、症状和影响；冻结相关发布或新增调用；保留日志、快照、原始报告和失败成本，避免重跑覆盖。先按身份/数据/模型/存储/队列分类，再采取最小范围恢复。

恢复后用固定样本验证输入、来源、评级、报告、权限和费用，再逐步恢复；24–48小时内形成根因、影响范围、处置、未解决风险、回归案例与责任人。涉及错误研究报告时创建新版本并说明修订，不删除旧证据。

## 3. 常见故障处置

| 症状 | 检查顺序 | 恢复与避免 |
|---|---|---|
| 模型401/403 | key有效性、组织/地区、tier provider、endpoint | secret manager轮换，冻结新调用；不把key打印日志 |
| 429 / timeout | provider配额、内部并行、retry/max_tokens、总deadline | 降低并发，冻结链内替代，记录成本；禁止无限重试 |
| NO_DATA / DATA_UNAVAILABLE | canonical ticker、市场日历、行情最新日期、vendor错误 | 区分供应商故障和标的无数据，必要时复核；禁止编价格 |
| 错误公司/异常价格 | instrument identity、来源/时点、币种/复权、缓存 | 暂停受影响报告，固定证据重跑；不仅换模型 |
| REVIEW/结构化失败 | schema能力、prompt版本、语言标签、文本回退 | 人工复核并加回归；不可转成Hold |
| checkpoint无法恢复 | 输入/图/模型签名、SQLite状态、磁盘权限、实例并发 | 备份后隔离新attempt；不直接全量删除checkpoint |
| 记忆串扰/记录缺失 | 共用路径、ticker/date去重、实验配置、文件锁 | 分离实验、只读导入核验；不得改写原始历史 |
| 文件保存失败 | 空间、权限、volume、report对象及manifest | 修复写入后校验；未落盘不标成功 |

## 4. 本地托管与未来云场景

本地事件先用operator凭据执行 `control pause_submissions --enabled "<事件原因>"` 和/或 `control freeze_publication --enabled "<事件原因>"`，必要时显式cancel在途任务；已发出请求可能继续计费。查看task/operations/audit的attempt、终态和unknown费用，保留失败对象与hash，不直接修改数据库或覆盖预测/观察。按恢复手册在新目录验证并撤销旧凭据后再启用；修正报告/评估使用新版本/新实验。以下outbox/云队列部分为目标场景。

队列重复消息从DB幂等/租约查起，不能只清队列；worker失联由租约新attempt接管，旧fencing拒绝提交；对象上传成功DB失败会留下孤立对象，按宽限期回收。取消/超时保留已消费费用，恢复任务冻结原配置/证据。

数据库故障停止接收新任务并保留队列，恢复后检查outbox积压、过期lease、终态和manifest一致性。事故中的DB restore必须按[恢复手册](backup-recovery.md)在隔离环境验证后切换。

## 5. 复盘记录

事件时间线、用户影响、报告ID、费用、版本、证据、根因、止损、恢复验证、通知决定、行动项（负责人/期限/需求或测试ID）。告警改进、数据补充和模型升级都走[变更发布](../07-governance/change-release-management.md)，紧急措施亦需补充审计。
